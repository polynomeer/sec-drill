# T16 운영·배포·복구·개인정보 준비 (프롬프트 16)

마지막 갱신: 2026-10-07. 기준: [24-observability](../../SecDrill-docs/docs/24-observability.md), [25-operations-deployment](../../SecDrill-docs/docs/25-operations-deployment.md), [14-database](../../SecDrill-docs/docs/14-database.md), [19-iam](../../SecDrill-docs/docs/19-iam.md).

프롬프트 16은 지표·로그·경보·서명·CI·drain/rollback/quarantine·백업/복원·export/삭제·tombstone·runbook을 아우른다. 이 중 로컬에서 staging·cloud 없이 **완전히 리허설 가능한** 것은 일부뿐이다(25의 "구분하라"). 이번 단계는 **개인정보 데이터주체 실행**을 구현·리허설로 완성했고(GAP-2, FR-10), 나머지는 아래 "남은 범위"로 남긴다.

## 구현·리허설 완료: 개인정보 데이터주체 실행

[ADR 0013](../adr/0013-privacy-data-subject-execution.md), [PRIVACY_ERASURE_REVIEW](PRIVACY_ERASURE_REVIEW.md) 참조.

- **export**: `POST /v1/exports`(본인 세션·전체), `GET /v1/async-jobs/{id}` 폴링, `GET /v1/exports/{id}/download`(소유자 확인·digest 검증). 소유자의 세션·제출·활성 평가·원장 safe_payload만 모으고 oracle·플래그·hidden test는 읽지 않는다.
- **삭제 요청·승인**: `POST /v1/deletion-requests`(재인증 `confirmationToken`=살아있는 세션 CSRF 증명, D-09까지 임시), SECURITY_ADMIN의 `POST /ops/v1/deletion-requests/{id}/decision`로 2인 분리.
- **삭제 실행**: 전용 `privacy_eraser` 역할이 `SECURITY DEFINER`·`search_path=public` 함수로 APPROVED·2인 확인 후 artifact bytes·row·리포트·checkpoint·추천·(ACCOUNT) identity 연결을 지우고 tombstone·receipt를 남긴다. 접속 revoke·Lab 종료를 선행한다. PII 없는 **원장 row는 유지**해 hash chain을 보존한다("payload unavailable", 14).
- **권한 분리**: `control_app`은 두 함수 EXECUTE와 `user_identities` DELETE가 없어 스스로 비식별화 불가.
- **retention·orphan sweep**: 만료 artifact bytes purge + soft-delete, 참조 없는 store object를 grace 후 회수(로컬 store 열거; S3는 D-15).
- **tombstone 재적용**: `reapply_tombstones`로 복원 뒤 되살아난 주체 재삭제.

### 검증(리허설)

`./gradlew :control-plane:app:test --tests 'secdrill.controlplane.privacy.*'` 9건 통과:

- `PrivacyExecutionTest`(7): ACCOUNT 삭제(bytes·identity·projection 삭제, 원장·receipt·tombstone·접속 revoke 확인), SESSION 범위 한정, 미승인 실행 거절·자기(비-admin) 승인 거절, export 조립·소유자 전용 다운로드·oracle 부재, retention purge, tombstone 재적용(삭제→복원→재삭제), orphan sweep.
- `PrivacyPrivilegeTest`(2): `SET ROLE control_app`로 `erase_deletion_request`·`reapply_tombstones` 실행과 `user_identities` DELETE가 모두 42501 거절; `privacy_eraser`는 실행 가능.

`scripts/check.py --strict` 14/14(V1..V12가 schema.sql과 동일).

## 구현·리허설 완료: 운영 통제(GAP-1)

[25](../../SecDrill-docs/docs/25-operations-deployment.md) "rollback"·"Runner 유실" 참조. 계약: `lab_pool`·`runner_quarantine`(V12).

- **Lab pool drain**: `POST /ops/v1/lab-pool/drain` {draining}(OPERATOR/SECURITY_ADMIN). draining 중 `requestLab`은 SERVICE_UNAVAILABLE로 신규 Lab을 막고, 기존 Lab·lease는 건드리지 않는다. 재개하면 다시 수락한다.
- **Node quarantine**: `POST /ops/v1/runners/{id}/quarantine` {reason}·`.../release`. quarantine된 runner는 `claimNext`·`claimJob`으로 새 작업을 못 얻고, start·heartbeat·complete가 STALE로 거절돼 현재 결과 token이 폐기된다(19, 25). heartbeat 거절로 lease가 만료되면 sweeper가 작업을 재배정한다. release로 복구.
- **DLQ 처리**: Outbox/consumer_inbox 기반은 T05에 있음. 운영자 DLQ 재처리 UI/엔드포인트는 절차 문서(남은 범위).

### 검증(리허설)

`OpsControlsTest`(4): drain 중 Lab 거절·재개 복구, quarantine된 runner claim 차단·release 복구, mid-job quarantine 시 heartbeat·complete STALE, 비운영 역할 403. `JobLeaseTest`·`CtfGradingTest`·`PatchGradingTest`·`ResponseDrillTest` 회귀 없음.

## 구현·리허설 완료: 관측(24)

- **운영 지표(Micrometer)**: `OperationalMetrics`가 저low-cardinality 게이지를 MeterRegistry에 등록한다 — outbox backlog·oldest age·publish failures, labs active·cleanup pending, grading SYSTEM_ERROR, jobs dispatch timeout, runners quarantined. sessionId 같은 고cardinality label·학습자 데이터는 넣지 않는다. HTTP 서버 지표(요청 지연·상태)는 actuator 기본 제공.
- **상관 id**: `RequestIdFilter`가 보안 필터보다 먼저 실행돼 모든 응답에 `X-Request-Id`를 달고 같은 값을 로깅 MDC(`requestId`)에 넣는다. 들어온 id는 짧고 안전한 토큰일 때만 수용(로그·헤더 주입 방지), 아니면 새로 발급. 거절된(401/403) 요청도 추적 가능.
- **스크래프 노출**: 지표는 학습자 데이터가 아니므로 learner 체인에 노출하지 않는다. 실제 스크래프는 보안 관리 포트·네트워크에서 하며 이는 배포 설정(절차).
- **구조화 로그**: 로깅 금지 필드(요청 content·flag·auth header·signed URL query)는 이미 지켜지고(T15), MDC에 `requestId`가 있어 JSON 인코더가 상관 가능하다. JSON 인코더(logback) 자체는 로그 포맷 전역 변경이라 배포 설정으로 둔다 — 필드 계약: timestamp·service·level·requestId·jobId·phase·errorCode·duration·attempt.

### 검증(리허설)

`ObservabilityTest`(3): 200·거절(401/403) 응답 모두 `X-Request-Id` 보유, 안전 id만 echo·불안전 id 치환, 게이지가 control 테이블에서 읽혀 quarantine 추가 시 +1.

## 남은 범위(다음 단계)

아래는 staging·cloud·외부 경보 수신자·서명 인프라가 있어야 **리허설**이 성립하므로 절차 문서로 진행한다.

- **경보·수신자(25)**: 위 지표에 대한 경보 규칙(24 표)과 실제 수신자 — 수신자 지정은 외부 설정, 절차 문서.
- **서명·환경 분리(25)**: 콘텐츠 서명은 구현됨. 이미지 SBOM/서명·dev/staging/pilot 분리는 배포 인프라, 절차 문서.
- **CI·staging(25)**: 파이프라인·canary·rollout은 GitHub·staging 필요, 절차 문서(현 CI 미실행 — push 안 함).
- **백업·복원(25)**: DB PITR·artifact versioning·서명키 복구와 월간 복원 리허설 — 실제 인프라 필요, 절차 문서 + 로컬 복원 리허설은 tombstone 재적용만 검증됨.
- **Runbook(25)**: broker 장애·Runner 유실·Lab escape·판정 오류·orphan·원장 mismatch 절차 문서.

## 전체 검사 메모

전체 `./gradlew check`에서 6건(`HealthReadinessTest` 1, `ContentSuiteTest` 5)이 실패했으나 **모두 격리 재실행에서 통과**했다. 실패 시 호스트에 다른 프로젝트 Docker 컨테이너가 23개 떠 있어 Testcontainers 병렬 실행이 포화된 상태였다(18분 소요). 두 테스트 모두 콘텐츠/패치 채점·actuator·보안 설정에 의존하고 이번 변경은 그 경로를 건드리지 않는다 → **호스트 Docker 과부하 flake로 판단**(D-10/호스트 부하, 이전 세션들과 동일 양상). 변경 영역 테스트(개인정보 9건, `OpsControlsTest` 4건, lease·채점 회귀)는 모두 통과.

## 미검증·주의

- 로컬·테스트는 소유자 역할로 접속해 앱이 삭제 함수를 직접 실행한다. 배포에서 전용 `privacy_eraser` 접속을 쓰는 구성은 D-14.
- `confirmationToken`은 진짜 재인증이 아니라 세션 보유 증명이다(D-09).
- 만료 세션 **전체 원장 삭제**는 append-only trigger를 조건부로 바꿔야 해 보류(보안 경계 변경).
- orphan 회수는 로컬 store 열거 의존. S3(D-15)에서 재검증 필요.
- 지표·경보·백업·배포의 **실제 운영 동작**은 staging·cloud가 없어 미검증.
