# T15 보안·채점 신뢰성 집중 리뷰

마지막 갱신: 2026-10-07. [17-sandbox-isolation](../../SecDrill-docs/docs/17-sandbox-isolation.md)·[18-threat-model](../../SecDrill-docs/docs/18-threat-model.md)·[19-iam](../../SecDrill-docs/docs/19-iam.md)·[20-execution-grading](../../SecDrill-docs/docs/20-execution-grading.md)를 기준으로 현재 구현을 점검한다. **정적 코드 리뷰 + 기존 적대 테스트 확인**으로 수행했고, 합성·로컬 환경에서만 검증했다. 실제 외부 대상에는 아무 공격도 하지 않았다. 강한 runtime이 없어(D-10) 실제로 검사할 수 없는 항목은 **안전으로 결론 내리지 않고 미검증으로 남긴다.**

## 방법

- 우선순위 11개 영역(소유권 가드, Artifact·SSE·Replay 접근, Gateway destination, secret·oracle 노출, compile/실행 격리, test tampering, result spoofing·stale fencing, 취소 후 자원, quota 우회, CSRF·XSS, 서명·공급망)을 코드에서 직접 확인했다.
- 소유권 가드 전수와 oracle·secret 유출 경로는 각각 전 저장소 스윕으로 교차 확인했다(핸들러 본문까지 읽어 가드 호출이 읽기·변경보다 먼저 실행되는지 확인).
- 판정은 파일 존재가 아니라 **통제 코드 + 통과하는 테스트**를 근거로 한다.

## 발견

### SEC-1 (낮음, 권고 — 미적용): 탐지 holdout 집계 피드백의 gaming gradient

- **위치**: `control-plane/submission/.../DetectionGrading.kt:105-111`. 매 제출마다 holdout(비밀 채점셋)의 혼동행렬 **정확 수치**(truePositives/falsePositives/falseNegatives/trueNegatives, p95)를 학습자 가시 `TEST_RESULT` 증거(SIMULATED, 스트림 노출)로 남기고, `holdout.recall/precision/f1/falsePositiveRate` 차원을 평가 뷰로 반환한다.
- **재현 조건**: DETECTION 제출을 반복하며 규칙 조건을 조금씩 바꾸고 각 제출의 holdout 혼동행렬 변화를 관찰. 제출 수 제한이 없어(제출 quota 미구현, [T14](T14.md) GAP) 좌표하강식으로 holdout 라벨을 부분 역설계해 일반화 없이 gate 통과를 노릴 수 있다.
- **영향**: 숨은 holdout의 "일반화 측정" 목적 약화(doc 18 평가 조작, doc 20 anti-tamper). holdout **데이터셋 자체·에피소드 라벨은 노출되지 않는다**(`IncidentResponse.kt:138-144`는 TRAINING만 제공, holdout 시드는 미제공 확인). 노출은 집계 수치에 한정되고, 세션당 Lab 1개 제약이 병렬화를 제한한다 → 낮음.
- **의도성 주의**: holdout **집계 지표를 학습자에게 보여주는 것 자체는 의도·테스트된 동작**이다(`ResponseDrillTest.kt:177-189`가 `holdout.recall`을 과적합 격차 교육용으로 명시 검증). 모듈 주석(`DetectionGrading.kt:37`)은 "training 지표를 차원으로 보여준다"고만 적어 실제 동작과 어긋난다.
- **권고 수정(미적용)**: 교육에 필요한 것은 비율 차원(일반화 격차 전달)이고, **정확 혼동행렬 수치**(`:108-109`)가 gaming gradient를 극대화한다. 학습자 가시 holdout 증거를 gate 결과+비율로 거칠게 하거나, 제출 quota로 재제출을 제한. 단 이는 채점 출력 형태(평가 계약) 변경이라 ADR·contracts·테스트를 함께 바꿔야 하므로 **사용자 결정 전까지 적용하지 않는다**(기존 테스트된 동작 되돌리기 금지 규칙).
- **검증**: `ResponseDrillTest.kt:208`은 `TEST_RESULT` 행의 type/source/trust만 확인하고 payload 필드는 확인하지 않으므로, 권고 수정은 해당 테스트를 깨지 않는다(적용 시 전용 회귀 추가 필요).

### SEC-2 (낮음, 관찰): 힌트 본문이 유일한 oracle→학습자 경로

- **위치**: `control-plane/lab/.../Hints.kt:76-78`(oracle `hints[].text`를 학습자에게 반환; 소유권 가드+순차 레벨+점수 차감으로 통제, ledger에는 레벨·차감만 기록).
- **영향**: `ContentValidation`은 힌트의 모양·레벨은 검사하나(`Validation.kt:145-149`) **본문이 정답을 담았는지는 검사하지 못한다**. 플랫폼 코드로 판정 불가한 저작 규율 문제(2인 검수 의존).
- **수정**: 코드 결함 아님. 저작 가이드·검수 체크리스트의 책임으로 남기고, 향후 runtime verifier가 힌트 본문 대 참조 해답 유사도 검사를 추가할 수 있음(범위 밖).

### 관찰(결함 아님)

- Outbox `last_error`는 broker 예외의 클래스명+메시지(500자 절단)를 ops 전용 컬럼에만 기록하며 학습자·oracle·토큰과 무관(`platform/Outbox.kt`). 어떤 로그도 플래그·토큰·시크릿·원시 제출 본문을 남기지 않는다(플래그 비교는 `MessageDigest.isEqual`, `ctf/Flags.kt:93-94`).

## 미검증(안전으로 결론 내리지 않음)

강한 runtime이 없어(D-10, KVM 미지원 호스트) **다음은 실제로 검사하지 못했고, 안전으로 판단하지 않는다.** 현재 모든 Lab·채점 결과는 데모다.

- 강한 격리(`lab-strong`/`grading-strong` microVM): guest escape, host mount/socket 부재, device passthrough, hypervisor·host kernel 취약점 — 실행 불가.
- 네트워크 격리 실측: outbound deny, metadata/host-gateway/private-range 차단, IPv6 우회, DNS 외부 resolution, 다른 Lab 접근 — strong runtime·전용 호스트에서만 검증 가능.
- CTF PASS는 runner가 서버측 접근 기록을 **정직하게 관측**한다는 신뢰에 의존한다(runner 탈취 시 매치된 플래그에 한해 PASS 위조 가능). 이는 설계가 명시한 잔여 위험(doc 18 "Agent 탈취")이며 mTLS·node enrollment·quarantine(D-17)은 미구현.
- 터미널 websocket transport·rootless Docker daemon·이미지 registry 서명(D-16) 실동작.
- Python monkeypatch/프로세스 조작에 대한 완전 차단은 가정하지 않는다(doc 20). 외부 supervisor 경계는 로컬에서만 확인.
- 부하·카오스(fork bomb·flood 상한의 실측), 다중 인스턴스·broker cluster.
- 실제 OIDC provider·브라우저 쿠키 동작(D-09).

## 결론

점검한 11개 우선순위 영역 전부에서 **학습자가 악용 가능한 플랫폼 결함은 발견되지 않았다.** 접근제어·fencing·격리 하드닝·서명·오류 처리에 전용 통제와 적대 테스트가 이미 갖춰져 있다. 실패 재현 테스트가 필요한 검증 가능한 결함이 없어 코드 수정은 적용하지 않았다(없는 결함에 대한 수정 조작 금지). SEC-1은 채점 계약 변경을 수반하므로 권고로만 남겨 사용자 결정을 기다린다. 강한 runtime 의존 항목은 D-10 해소 전까지 미검증으로 유지한다.
