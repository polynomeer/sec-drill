# T18 파일럿 출시 준비 Evidence Dossier와 최종 판정 (프롬프트 18)

마지막 갱신: 2026-10-07. 기준: [01 제품계획](../../SecDrill-docs/docs/01-product-plan.md), [02 PRD](../../SecDrill-docs/docs/02-prd.md), [03 MVP](../../SecDrill-docs/docs/03-mvp-scope.md), [26 테스트전략](../../SecDrill-docs/docs/26-testing.md), [25 운영](../../SecDrill-docs/docs/25-operations-deployment.md), [18 위협모델](../../SecDrill-docs/docs/18-threat-model.md), [acceptance-matrix](../../SecDrill-docs/examples/acceptance-matrix.csv).

## 판정: NO-GO (외부 학습자 파일럿)

제한 파일럿(학습자가 공격 Lab을 사용하는 MVP 범위)은 **지금 시작할 수 없다.** 결정적 사유는 **강한 격리가 검증되지 않았고(NFR-01, D-10)**, 그 외 필수 release gate(콘텐츠 출판 가능성, 성능 측정, 백업·복원 리허설, 경보 수신자·운영 담당자)가 충족되지 않았다는 점이다. 이들은 필수 검증이며 낮은 위험으로 임의 처리하지 않는다(프롬프트 요구, 18 "하나라도 재현되면 외부 Lab 개방 중단").

- **내부 개발·데모**(local-trusted, 합성 데이터, 운영 사용자 없음)는 계속 가능하다. 지금까지의 모든 결과는 demo다.
- 아래 조건을 모두 충족하면 **CONDITIONAL GO → GO** 재평가 대상이 된다(조건·책임자는 6절).

## 2. strong isolation 검증

**미검증(release gate 미통과).** KVM 없는 호스트라 `lab-strong`/`grading-strong` microVM을 실행하지 못한다(D-10). [17](../../SecDrill-docs/docs/17-sandbox-isolation.md) 출시 검증(IPv4/IPv6/DNS/metadata/control/다른 Lab 접근 실패, mount/socket 부재, fork/memory/output flood 상한, 취소 후 late provision 회수, Control outage 중 hard TTL, escape 의심 시 quarantine)은 local-trusted에서 일부만 확인됐고 강한 격리의 증거가 아니다. 외부 파일럿은 선택한 강한 runtime을 require-isolation으로 강제하고 없으면 fail closed여야 한다 — 미구현.

## 3. 6개 콘텐츠 품질

[content-verification](content-verification.md), [T13](T13.md): 3 base + 3 transfer 사건의 참조 패치가 VERIFIED, 핵심 mutant가 모두 해당 gate에서 NOT_VERIFIED로 검출됨(`ContentSuiteTest`·`PatchGradingTest`·`DetectionSeedSuiteTest`). **단, 전부 local-trusted demo이며 출판 게이트는 runtime verifier 부재로 INCOMPLETE** → 실제로 출판할 수 없다.

## 4. 채점·중복·stale 결과

불변식 입증(정확성, demo): FLAG는 서명 receipt+서버 관측으로 verdict 계산(위조 불가), PATCH/DETECTION은 서버 계산, 중복 전달은 한 번만 반영, stale/late token은 거절·감사, SYSTEM_ERROR는 사용자 FAIL로 바뀌지 않음([T15](T15.md)·[T17](T17.md) 추적표). 부하 하 동작·회복시간은 미측정.

## 5. 보안 발견과 잔여 위험

[T15](T15.md): 11개 우선순위 영역 정적 리뷰+적대 테스트에서 **학습자가 악용 가능한 플랫폼 결함 없음**, 코드 수정 불필요. 잔여 위험: 강한 격리 미검증(최대), runner의 정직한 관측 신뢰(mTLS·quarantine은 quarantine만 구현, D-17), 힌트 본문 저작 규율, 탐지 holdout 집계 gaming(SEC-1, 보류), hypervisor/host kernel 취약점(D-10 이후 잔존).

## 8. 백업·복원·삭제 리허설

삭제 실행·tombstone 재적용은 리허설 통과([T16](T16.md), `PrivacyExecutionTest`). **DB PITR/복원·artifact versioning(D-15)·서명키 복구의 실제 리허설은 미수행**(B4). 월간 복원 리허설 절차는 [OPERATIONS](OPERATIONS.md).

## 9. 경보 수신자·운영 담당자

**미지정.** 25에 따라 실제 경보 수신자가 없는 파일럿은 시작하지 않는다(B5·B6).

## 10. rollback·중단 조건

[OPERATIONS](OPERATIONS.md): rollback(이전 이미지+호환 schema, drain 선행, frozen imageDigest 유지), 중단 조건(5xx>5% 2분, host RAM>90%, cleanup 지연>5분, cross-session 영향, escape 의심). drain·quarantine·stop은 구현.

## 11. 10명 파일럿 계획 (B1~B6 충족 후 실행)

- **참가 조건**: 동의한 보안 학습자 10명, 제한 가입, 20 Lab 한도, 합성 데이터만, 개인정보 최소(issuer/subject). 실제 공격 대상·고객 데이터 금지.
- **온보딩**: 계정(OIDC)·동의·범위 안내·CTF 1건으로 도구 적응 → base 3사건 → transfer 3사건.
- **관찰 항목**: Lab provisioning 지연·실패, 채점 SYSTEM_ERROR·stale, orphan·DLQ, 힌트 노출, 접근성 이슈, 중단 조건 트리거.
- **학습 효과·Transfer**: base 대비 transfer 사건의 독립 해결률·시간·힌트 의존도. 스킬 projection(UNKNOWN/confidence)·추천 이유 추적.
- **이탈**: 단계별 중도 이탈 지점·사유.
- **평가 신뢰도**: 참조 VERIFIED·mutant 검출 유지, demo/格리 표기 정확성, 재채점 분포.
- **실제 사용자 성과: 아직 없음.** 파일럿 미실행이므로 학습 효과·Transfer·이탈·신뢰도 데이터는 존재하지 않는다.

## 12. 배포 계획 (승인 가능, 미실행)

1. B1~B7 충족 확인(특히 B1 강한 runtime 검증, B5 경보 수신자, B6 담당자).
2. staging에 운영 동형 배치 → [T17](T17.md) 2.1 성능·주입 측정 → 목표 미달 수정·재측정.
3. 콘텐츠 runtime verifier로 6개 사건 출판(2인 승인·서명).
4. DB 백업·월간 복원 리허설 1회 통과(B4).
5. canary → 제한 파일럿(10명) rollout. 배포 승인 기록(담당자·version/digest·검증 결과·rollback 경로·경보 수신자) 작성.
6. 중단 조건 상시 모니터; 1건이라도 재현되면 외부 Lab 개방 중단·영향 범위 확인·수정·재검증.

**최종 배포는 실행하지 않는다.** 위 계획은 승인 대상이며, 경성 조건(B1·B5·B6) 미충족 시 승인 불가.
